# 八幡地区 常駐4隻体制検証 作成条件

2026年10月4日。ユーザーの発言を最優先する。過去のAIによる用語・分類・推測を正解としない。

## 目的と判定

製鉄曳船の減船を1隻、常駐4隻とする方針について、日本製鉄へ運航上の必要性を示す基礎データを収集する。同時に自社として4隻が合理的かを検証し、料金体系見直しへ進む基盤とする。4隻だけに都合のよい結果を作らない。現在は基礎データの収集段階であり、帳票完成や既往の88日という数値の再現だけを達成目標にしない。

## 元資料

上田提出4点を基盤とする。原本・ZIPは変更しない。03_失敗版参考のレイアウト、項目名、集計式を流用しない。資料一覧のSHA-256と照合し、読めなかった資料を明示する。2026年のPDF3点は予定の版比較に使い、2025年度の実績へ結合しない。2025年度の前日最終予定表・当日の変更連絡は現時点で本一式に含まれない。日鉄提出スライド・旧集計プログラムも本一式に含まれない。数値の不一致は原因を説明し、確認できない原因は未確認とする。

## 調査の順番

1. 元帳R7年度（2025年4月1日～2026年3月31日）の実績で、同時3隻以上となった日を抽出する。「同日3隻使用」「1本船に3隻使用」と混同しない。複数本船・複数作業の時間を重ね、物理的に同じ船は重複計上しない。作業時間が基地発・基地着か未確認なら、抽出は候補として扱う。
2. 上田が対象日の前日最終確定予定を突き合わせる。翌日の出勤を手配した最終確定を保存し、対象時間帯だけでなくその日全体の予定を照合する。作業予定タグ数、出勤手配隻数、同時必要隻数は別の数値として表示する。
3. 前日確定との対比とは別に、全作業の変更・キャンセルを調べる。変更があった箇所を入力し、変更なしと確認済みの日と未確認の日を区別する。実績が3隻未満になった日、当日全船休航、実績元帳にない取消しも含める。複数回の変更を残し、前日最終確定を上書きしない。
4. 製鉄曳船・西日本海運の入渠、西日本海運の全他港作業、他社配置を調べる。他社入渠は分かる範囲。西日本海運の他港作業を関豊丸・長豊丸だけに限定しない。
5. 基地発から基地着までの標準時間を設定する。八幡タグは上田、西日本海運タグは西日本海運担当者が、会社・基地港・残存バース・作業内容ごとに確認する。LNG入港・出港・警戒は分ける。元帳の「予定時間」から基地発・基地着を推計する場合、時刻の基準と前後の移動時間も確認する。合計所要時間だけで開始位置を決めない。全実績に基地発・基地着の手入力を求めない。標準時間による推計と実測を表示上区別する。

## 入力画面

担当者は元帳を再入力しない。会社・船名・実績時刻・バース等は元帳から表示する。対応関係を画面で選択・確認でき、独自IDを入力者に手入力させない。元帳の1作業とタグ別行を区別する。通船とタグを区別し、基地発後取消し等の実拘束を実施作業へ誤算入しない。

入力シートは以下の役割を持つ。表示上の名称はこの日本語を使う。余分な補助計算は入力者の目に触れない位置へ置く。

| シート | 入力者が行うこと | 主な入力項目 |
|---|---|---|
| はじめに | 目的・最初の操作を見る | 入力順、担当者、入力色、未確認の意味 |
| 実績 | 取り込まれた元帳を見る | 原則自動表示。休船呼出の最初の対応行を選んで関連付け可能 |
| 前日確定 | 対象日の最終予定表を照合する | 前日最終予定時刻、予定タグ、確定時点、翌日の出勤手配、情報元、確認状況 |
| 変更・キャンセル | 全作業の変更のあった箇所を追加する | 作業選択、連絡日時、変更前後の時刻・タグ・隻数、取消し、理由、時間調整、呼出船と呼出日時、情報元 |
| 入渠 | 作業に使えない期間を記録する | 会社、船名、入渠開始日、作業復帰日、情報元 |
| 他港作業 | 西日本海運の全他港作業を記録する | 船名、作業港、基地発日時、基地着日時、情報元。実時刻不明は確認状況を残す |
| 他社配置 | 若松・関門等の他社の体制を記録する | 会社、船名、配置港、対象期間、入渠・他港拘束が分かれば記入、情報元、確認日 |
| 標準時間 | 担当者が見込みの拘束時間を確認する | 会社、基地港、バース、作業内容、予定時刻の基準、移動・作業・帰航時間、適用期間、確認者 |
| マスター | 会社・船名などを追加する | 会社、船名、基地港、適用期間、情報元、確認状況。その他選択肢も追加可能 |
| 集計 | 対比結果と不足情報を見る | 自動表示。全作業／残存作業、安瀬／応援、実測／標準時間推計、確認済み／未確認を区別 |

表内は収集すべき情報の一覧であり、各入力者に全欄を一度に要求しない。最初の入力場所を案内し、元資料で埋められる項目は自動表示する。必要隻数・時間調整・応援回答等の詳細は、3隻と4隻の差を比較する代表事例で入力できるようにする。各画面に目的、見る元資料、入力箇所、集計先を短く書く。薄黄色＝入力、薄灰色＝自動とし、項目名にも入力／自動を明記する。○と船名選択は入力規則で扱い、VBA・マクロ・独自ボタンを使わない。

休船からの呼出は製鉄曳船・西日本海運を対象とする。同じ船の同じ呼出に複数作業がぶら下がっても1回と数える。複数船を呼び出した場合は、船ごとの呼出が分かる形とし、名前を自由記述で並べる方式を避ける。呼出実績と常駐船腹の不足を同一視せず、乗組員の出勤手配と利用可能な船体の不足を区別する。

安瀬は若松との按分配船である。応援へ合算しない。若松は矢野海運・洞海マリン、関門は関門他社・春風海運の配置体制を分かる範囲で記録する。洞海マリンの長崎移動などの例を実際にあった出来事と扱わない。他社の配置と依頼への対応可否は別である。応援参加船の抽出は補助機能にとどめ、前日予定あり・実績全船休航という日を落とさない。

## 3隻と4隻を比較するための記録

代表事例について、各作業の必要タグ隻数、時間調整の許容範囲、動かせない理由、入出港・移動・基地帰着の拘束、入渠・他港拘束、休船・乗組員の出勤、応援の依頼時刻・回答時刻・必要到着時刻・対応可能時刻・根拠を収集する。未確認は判定保留とする。他社が実績で参加していないことを「応援不可」と扱わない。

同じ作業・時間条件・運航制約・確認された応援条件で3隻と4隻を比較する。全作業と、電炉化後に残る作業を分ける。LNG・鋼材を中心に残存区分を確認し、高炉原料を除いて再構成する。安瀬・副原料等の将来取扱いが未確認なら、条件を明示して別ケースとし、AIの判断で残存を決めない。過去の呼出が高炉原料に起因する場合、将来の必要性へそのまま転用しない。

LNGが必要5隻の条件なら4隻でも応援1隻が要るため、4隻単独で充足としない。3隻の場合の応援2隻との違いを確認する。必要な応援がその時刻に来られるかを検証する。2025年の他社配置は将来の応援確約ではない。予定上の4隻出勤は、4隻の同時必要性の証明ではない。選別した対象日だけの予定対比を、年間全日の前日予定集計と呼ばない。計算上の遅延と実際に発生した遅延は区別する。4隻でも不足する条件、3隻で対応できる条件も表示する。採算検証は別途必要であり本入力資料だけで採算を断定しない。
